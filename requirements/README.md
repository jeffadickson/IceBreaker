# Requirements management

The project has prior StrictDoc `.sdoc` requirements in `apps/rink-local/requirements/`, plus workflow and parent-portal proposals in `requirements/workflow-proposal/`. The HTML manual explains policy and target behavior, **not completed functionality**.

Recommended lifecycle: Proposed → Reviewed → Accepted → Implemented → Verified → Released. Stable IDs are never reused. Maintain a requirement-to-test mapping and attach evidence to each release.

**Proposed tooling:** StrictDoc, source-controlled `.sdoc` files, exported matrices, plus CI validation. Do not mark a design requirement verified solely because this documentation exists.
