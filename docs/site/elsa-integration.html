Elsa workflow integration

Development v2.7: IceBreaker now invokes Elsa 3.8 as a separate .NET workflow worker for accepted scoresheet transitions. It does not yet delegate the official scoring or certification decisions to Elsa.

Architecture

Scorekeeper → SQLite game journal + workflow transition
                               ↓ (same transaction)
                    elsa_bridge_outbox
                               ↓ (retry worker)
                 Elsa ASP.NET Core service
                               ↓
                    Elsa workflow Sequence

All signature, role, event-sequence and document-digest checks remain in IceBreaker. A failed Elsa worker can never roll back a confirmed goal or referee signature.

Running the service

$env:ICEBREAKER_ELSA_BRIDGE_KEY = 'replace-with-long-random-secret'
dotnet restore services/elsa-workflows/IceBreaker.Elsa.csproj
dotnet run --project services/elsa-workflows/IceBreaker.Elsa.csproj --urls http://127.0.0.1:8094

Configure a private-only worker to call flush() from services/elsa-workflows/bridge-outbox.js with the service URL and matching key. The current proof of concept does not yet include a scheduled service supervisor.

Verification and limitations

Run node --test tests/integration/elsa-bridge.test.js. The Elsa server needs the .NET 8 SDK, package restore and separate compile/runtime validation. Elsa Studio, a persistent inbox and long-running human approval activities are future work.

Security: This development adapter uses a shared internal secret and in-memory receiving deduplication. Do not expose the host on the public internet; deploy behind TLS/private ingress and replace the inbox before production.

See Elsa 3 server documentation and requirements in the repository.
