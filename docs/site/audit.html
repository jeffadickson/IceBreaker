ICEBREAKER / EVENT LOG & RECOVERY

All-action logging and recovery

IceBreaker distinguishes authoritative scoring events from low-level interaction logging.

Three records

RecordContentAudience
SQLite event journalAccepted goals, penalties, clock changes, mercy transitions, correctionsAuthorized scoring and certification
Operator action auditButton presses, drafts, edits, cancels, confirmations, rejected commands, errorsAuthorized operations/security
Readable event mirrorText/JSONL projection of committed journal for diagnosticsAuthorized download and recovery

Field requirements

Every action should carry UTC timestamp, game ID, actor/device, action, correlation ID, applicable period/time, success/failure, and sanitized parameters. Never log passwords, tokens, raw private personal data, or complete request secrets.

Recovery

  1. Stop the clock and preserve the underlying database and original audit files.
  2. Check database integrity and event sequence before attempting repair.
  3. Rebuild only derived projections from the authoritative journal; never guess missing committed events.
  4. Reconcile unsent outbox entries, resume after proper game assignment verification, require official review if needed.
Current local logs and hash chaining are development safeguards—not an immutable external archive or guaranteed independent backup.
