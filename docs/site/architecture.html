ICEBREAKER / ARCHITECTURE

System architecture

Local rink station (offline authority)
  ├─ C# sport/game engine [experimental]
  ├─ SQLite journal + audit + sync outbox
  ├─ Operator touchscreen / clock controller
  └─ Hardware/PA adapters [planned]
           │ authenticated incremental sync [planned]
           ▼
Central league API + event ingestion [planned]
  ├─ Spectator projection → parent Live
  ├─ League/roster/schedule database
  ├─ Certification → signed revision [planned]
  ├─ Workflow engine (Elsa) [planned]
  └─ Notification queue → opted-in email [planned]

Separation rules

  • Sport-neutral domain services shall not depend on hockey-specific rules.
  • Only a designated game authority accepts official scoring commands.
  • Spectator-facing projections never expose private operator audits or authentication material.
  • Certification is bound to an immutable snapshot/digest, not a mutable “current score” string.
  • External cloud providers (TTS, email) are noncritical adapters.

Repository layout

The existing runnable vertical slice remains grouped under apps/rink-local/ for import-path compatibility. Future split into Avalonia rink console, ASP.NET Core central gateway, hockey module and notification service is described in REPO_ROADMAP.md.
