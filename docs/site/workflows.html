ICEBREAKER / WORKFLOW & POLICIES

Workflow and league policies

The recommended future engine is Elsa Workflows for server-side, durable .NET workflows. A league may use a versioned JSON policy as the user-facing configuration, compiled/validated into an approved workflow definition.

Configurable

  • Eligible approver role(s) and number of signatures.
  • Review timeout, escalation, disputed/reopened states.
  • Certification notifications and event publication timing.
  • Mercy thresholds, eligible periods, latched/dynamic activation.
  • Report delivery options and tiebreaker policies.

Never configurable away

Authentication, game assignment authorization, event sequencing, immutable audit, cryptographic revision binding, youth data access policy, and idempotency checks remain enforced in the core.

Example file

{
  "policyId": "youth-hockey-standard",
  "version": 1,
  "schemaVersion": "1.0",
  "gameCertification": {
    "livePublication": "provisional",
    "onFinalSubmission": "pending_review",
    "requiredApprovals": [{"role": "referee", "count": 1}],
    "requireAllEventsSynchronized": true,
    "allowUnresolvedAttributions": false,
    "requestCorrectionOnDiscrepancy": true,
    "officialApprovalDueHours": 48,
    "escalationRole": "league_administrator",
    "sendReportOn": "certified",
    "reopenRoles": ["league_administrator"]
  },
  "parentPortal": {
    "followTeams": true,
    "followPlayersWithGuardianPrivacyEnforcement": true,
    "showFullOfficialLiveScore": true,
    "dailyEmailLimit": 5,
    "gameReportEmail": "opt_in",
    "reportCorrectionPolicy": "send_revision_notice",
    "playerVisibility": "league_approved",
    "guardianConsentRequiredForMinorProfile": true
  }
}

The included configuration is an example policy, not a functioning Elsa workflow. New definitions require review, tests, and version pinning to each game.
