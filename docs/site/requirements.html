ICEBREAKER / REQUIREMENTS & DECISIONS

Requirements management

The repository keeps existing `.sdoc`/CSV registers under apps/rink-local/requirements/ and recent workflow proposals under requirements/workflow-proposal/.

Recommended StrictDoc workflow

  1. Write a concise, atomic requirement with permanent ID and measurable acceptance criteria.
  2. Label priority P0/P1/P2 and status Proposed/Accepted/Implemented/Verified/Released.
  3. Record decision ownership, source, dependencies and affected configuration versions.
  4. Link unit, integration, E2E and security tests; retain CI run identifiers as evidence.
  5. When a requirement changes, revise it and explicitly evaluate impact on signed game snapshots.

Selected invariants

  • All official game actions generate immutable authoritative events.
  • All meaningful operator actions, including drafts/cancels, generate private audit entries.
  • Live parent scores do not hide goals under mercy rules.
  • Unknown scorer/assists use TBD, not an invented roster player.
  • Only version-locked, authorized scoresheets can become certified.
  • Parent follow/report/email must be consent- and privacy-controlled.

See requirements/traceability.md and testing guide for a starter verification map.
