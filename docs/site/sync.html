ICEBREAKER / REMOTE RINK SYNC

Remote rink synchronization

Planned for a production release. The included Node server is localhost-only; it is not an authenticated multi-rink gateway.

Normal flow

  1. Assign a game to an authorized rink station and user.
  2. The rink commits each accepted action to the local event journal and transactional outbox before acknowledging it.
  3. When online, the station batches events with game ID, stable IDs, event sequence and idempotency key.
  4. The central gateway verifies device identity, game assignment, sequence completeness and payload validity.
  5. Approved provisional projections update the parent's live feed without certifying the score.
  6. After final and official approval, the certified revision updates standings and statistics.

Fault cases

ConditionRequired behavior
Lost connectivityContinue scoring locally, queue events, show sync status
Duplicate eventReturn idempotent acknowledgement, never score twice
Sequence gapHold/protect projection and request missing events
Device replacementRebind authorized game session with fencing
Clock crashRecover stopped; never silently count through downtime

Trust model

A station credential establishes origin, not the correctness of a referee-approved result. Official certification is a separate authorization step.
