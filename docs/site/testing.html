Release-blocking scenarios

AreaPass criterion
Goal entryOne confirmed goal increments exactly once; TBD correction does not re-score
AuditingAll operator actions (including canceled drafts) recorded privately; no secrets exposed
MercyOnly arena display capped; parents see full true score/events
RecoveryRestart never extrapolates game clock; committed events persist
Remote syncDuplicate/reordered/missing events cannot corrupt or certify game
CertificationCorrect assigned official signs exact digest; stale or revoked approval rejected
Parent emailOnly opted-in recipients; one report per certified revision; unsubscribe works
PrivacyNo protected player/guardian information reaches public projection

Traceability

Keep stable StrictDoc IDs and connect requirement → code → test → CI evidence. A status of “documented” is not “verified”. The repository includes a CI workflow, but it should not be treated as passed until CI actually runs on GitHub.

Current evidence

The Node test suite exercises the local prototype; C# build/tests and browser E2E testing require independent verification in a target environment. Run both before release.
